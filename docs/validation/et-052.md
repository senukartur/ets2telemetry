## PR-1: the protocol v1 minor-2 contract and the pure break rules (October 26, 2026)

Based on main `c9386e5`.

### Behavior

- `packages/contracts/src/protocol-v1.ts` implements minor 2. `V1_MAX_MINOR` is 2 and `V1Minor` is `0 | 1 | 2`. The envelope minor selects the state schema: minor 0 has neither extra key, minor 1 has `gearbox`, minor 2 has `gearbox` and `nextMandatoryBreak`. The break is a `Measure<'min'>` whose available `value` is a plain JSON integer in the s32 range (`-2147483648` to `2147483647`), not the decimal string of `GameMinutes`.
- `negotiateV1` selects `min(hello maxMinor, its own maxMinor)`. Before this PR it selected 0 whenever the offer was below its own maximum, which was correct while the maximum was 1 and would have served a minor-1 client minor 0 against a minor-2 server (MB2).
- `maxMinorOf`, `version()` (in `protocol-v1.ts`) and `minorOf` (in `protocol-v1-delivery.ts`) accept 0 to 2 and reject anything else. Every stateless entry point still defaults to minor 0.
- `NOT_SUPPORTED_BREAK` is a frozen `{available: false, reason: 'not-supported', unit: 'min'}`. It is added early, in PR-1; only tests use it, and nothing projects it until PR-4.
- The application and the simulator still offer minor 1 and nothing serves minor 2: the service's `V1_CLIENT_MAX_MINOR` (`apps/desktop/src/v1-ingestion.ts`), the simulator producer's `negotiateV1` maximum and the simulator client's default offer (`tools/telemetry-simulator/src/v1/`) are pinned to the literal 1 with a comment that PR-4 flips them. The plugin and the broker are unchanged and answer at most minor 1. Storage's `validateServerMessage` uses `V1_MAX_MINOR`, so it can now validate a minor-2 message, but nothing delivers one.
- `packages/telemetry-core`:
  - `mandatory-break.ts` (new): `BREAK_SOON_MINUTES` 120, `breakUrgency` (zero or less `due`, 1 to 119 `soon`, 120 or more `normal`) and `formatMandatoryBreak` (clamp at zero, then `formatGameDuration`).
  - `NormalizedLiveState.nextMandatoryBreak: Reading<number>`: the signed raw value from a minor-2 state; `not-supported` for a v1 state below minor 2; `not-carried` under v0 and in the trip accounting's synthetic step state.
  - Live-view field `mandatory-break` in the `time` section after `deadline`, with the `game-time` note, v1 only (not in `V0_CARRIED_FIELDS`), and an optional `urgency` (`soon` or `due`) on a current value row.
- No settings, IPC, preload, payload, storage, schema, native, overlay or dashboard behaviour changed. Because the new field id extends `LiveFieldId`, `apps/desktop/src/strings.ts` gained its English label (the label table covers every id) and `apps/desktop/src/live-dashboard-text.ts` skips the row through `NOT_YET_SHOWN_ROW_IDS`, so the Live card is exactly as before; PR-4 removes that skip together with the localized label and the dashboard row. PR-4 must add the Russian label for `mandatory-break` to the app copy (`apps/desktop/src/i18n`, `screens/app-copy.ts`) when it removes `NOT_YET_SHOWN_ROW_IDS`; PR-1 added only the English entry that the exhaustive table needs. `GAME_HISTORY_RECORDING` is unchanged.

### Fixtures

The minor-0 fixtures (`tests/fixtures/protocol-v1/*.json`, manifest, streams), the minor-1 corpus (`minor1/**`) and `tests/fixtures/protocol-v0` are byte-identical: `git status` shows no change to any of them.

## PR-3: plugin capture and the minor-2 endpoint (October 26, 2026)

Based on PR-2's head `5e29b5f`. The plugin now captures `mandatory.break` and serves minor 2, but the running application still offers at most minor 1, so nothing is shown and nothing user-visible changed.

### Behavior

- `sdk-adapter.{hpp,cpp}`: `Field::mandatory_break` sits before `world_placement`, in the scalar `State::channels` array (ten entries now; `Field::count` is 11). Its spec is `mandatory.break`, s32, unit `min`, multiplier 1, range −2,147,483,648 to 2,147,483,647 (exact in a double), registered with the same `each_frame | no_value` flags as the other common channels. A NULL value is `not-observed`, a value of another SDK type is `invalid`, and zero is an available 0. Freshness is unchanged: it is the existing `observed_in_frame_` bookkeeping, so a timer restart or a `game.time` regression clears a registered break that the new frame has not delivered, and a truck configuration clears it like the other dynamic channels.
- Registration is optional for this field only: any result other than `ok` (the tests cover `not_found`, `unsupported_type`, `unsupported`, `generic_error`, `not_now` and `invalid_parameter`) makes the reading `not-supported`, the channel is not registered or unregistered, and initialization continues. The core channels keep the strict rule; two tests refuse `truck.speed` and `truck.world.placement` and expect initialization to fail and clean up.
- The callback is an ordinary SDK-thread copy of one value: no SDK call, no allocation, no `eventSeq`, no record, no revision. It also does not call the v0 diagnostic `observe()`, and it does not advance the adapter's boundary order (`next_order()` is skipped for this field only), because that order is part of the v0 snapshot, of every CAP0 envelope and of the v1 state's `boundaryOrder`: a game that provides the channel must give the same v0 snapshots and CAP0 envelopes as one that does not (a deviation from treating it like the other channels; the reasoning is in the paragraph on changed expectations below). `publish_v1` converts the reading to `StatePod::next_mandatory_break_min` (`Field<int32_t>`) with `v1_reading_s32`, which converts the exact double back to an int32 without the multiplier path (a differently named function instead of an overload, because the two would take the same argument type).
- `protocol-v1-producer.cpp`: the gearbox is now emitted for `minor >= 1` (it was `minor == 1`, which would have dropped the gearbox from a minor-2 state), and `nextMandatoryBreak` for `minor >= 2` as `{"available":true,"value":95,"unit":"min"}`, a plain JSON number (unavailable: `reason` and `unit`). Minor-0 and minor-1 bytes are unchanged.
- `v1-server.cpp`: `endpoint_max_minor = highest_minor` (2). The plugin selects min(hello `maxMinor`, 2), so offers of 2 and 3 get minor 2, an offer of 1 still gets the original minor-1 bytes and an offer of 0 the original minor-0 bytes. The PR-2 pin comment and the producer's PR-2 comment are replaced.
- No fixture, `apps/`, `packages/` or `tools/` file changed. TD-021 gains no new trigger in code: a minor change inside one plugin session stays `SESSION_CONFLICT`. Release constraint (ET-052): the claim that a supported update cannot cause it (plugin setup never replaces the DLL while a game runs) holds only if the plugin that serves minor 2 (PR-3) and the application that offers minor 2 (PR-4) ship in the same release. A release with PR-3 but not PR-4 has a plugin that can serve minor 2 while the application offers 1: the application records a session at minor 1 (`plugin_sessions.protocol_minor` = 1), and if the user then updates to the PR-4 build (which offers 2) while that game is still running, the same plugin session negotiates minor 2, `upsertSession` fails with `SESSION_CONFLICT`, recording fails closed until the game restarts, and nothing committed is lost. `GAME_HISTORY_RECORDING` is true, so this path is reachable. It is not a code defect in PR-3; PR-3 and PR-4 must be released together, or the owner must explicitly accept the conflict. No release is authorized by this work.

### Tests

Expected values are the hand-written `minor2` fixtures and values written out in the tests. REG-009 (zero, unavailable and units), REG-003 and REG-010 are the scenarios touched.

- `v1-producer-contract-mandatory-break` (and the ASan twin): the encoder's minor-2 checkpoint equals `minor2/checkpoint`; the snapshot equals `minor2/snapshot`; 0, −30, both s32 extremes, `not-observed`, `not-supported` and `invalid` equal their `snapshot-break-*` fixtures (with the fixtures' own `seq` and times); a default copy is `not-observed`; the value is a JSON number; minor 0 and minor 1 equal the frozen and `minor2/*-minor-0|1` fixtures and are byte-identical with and without a break; the default and minor-1 encoders refuse a minor-2 frame; welcome, event, gap, clock reply and end equal their minor-2 fixtures; the worst-case minor-2 state fits 64 KiB; the minor-2 `Consumer` accepts the stream and refuses a minor-1 snapshot within it.
