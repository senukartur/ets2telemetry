## PR-1: the protocol v1 minor-2 contract and the pure break rules (October 26, 2026)

Based on main `c9386e5`.

### Behavior

- `packages/contracts/src/protocol-v1.ts` implements minor 2. `V1_MAX_MINOR` is 2 and `V1Minor` is `0 | 1 | 2`. The envelope minor selects the state schema: minor 0 has neither extra key, minor 1 has `gearbox`, minor 2 has `gearbox` and `nextMandatoryBreak`. The break is a `Measure<'min'>` whose available `value` is a plain JSON integer in the s32 range (`-2147483648` to `2147483647`), not the decimal string of `GameMinutes`.
- `negotiateV1` selects `min(hello maxMinor, its own maxMinor)`. Before this PR it selected 0 whenever the offer was below its own maximum, which was correct while the maximum was 1 and would have served a minor-1 client minor 0 against a minor-2 server (MB2).
- `maxMinorOf`, `version()` (in `protocol-v1.ts`) and `minorOf` (in `protocol-v1-delivery.ts`) accept 0 to 2 and reject anything else. Every stateless entry point still defaults to minor 0.
- `NOT_SUPPORTED_BREAK` is a frozen `{available: false, reason: 'not-supported', unit: 'min'}`. It is added early, in PR-1; only tests use it, and nothing projects it until PR-4.
- The application and the simulator still offer minor 1 and nothing serves minor 2: the service's `V1_CLIENT_MAX_MINOR` (`apps/desktop/src/v1-ingestion.ts`), the simulator producer's `negotiateV1` maximum and the simulator client's default offer (`tools/telemetry-simulator/src/v1/`) are pinned to the literal 1 with a comment that PR-4 flips them. The plugin and the broker are unchanged and answer at most minor 1. Storage's `validateServerMessage` uses `V1_MAX_MINOR`, so it can now validate a minor-2 message, but nothing delivers one.
- `packages/telemetry-core`:
  - `mandatory-break.ts` (new): `BREAK_SOON_MINUTES` 120, `breakUrgency` (zero or less `due`, 1 to 119 `soon`, 120 or more `normal`) and `formatMandatoryBreak` (clamp at zero, then `formatGameDuration`).
  - `NormalizedLiveState.nextMandatoryBreak: Reading<number>`: the signed raw value from a minor-2 state; `not-supported` for a v1 state below minor 2; `not-carried` under v0 and in the trip accounting's synthetic step state.
  - Live-view field `mandatory-break` in the `time` section after `deadline`, with the `game-time` note, v1 only (not in `V0_CARRIED_FIELDS`), and an optional `urgency` (`soon` or `due`) on a current value row.
- No settings, IPC, preload, payload, storage, schema, native, overlay or dashboard behaviour changed. Because the new field id extends `LiveFieldId`, `apps/desktop/src/strings.ts` gained its English label (the label table covers every id) and `apps/desktop/src/live-dashboard-text.ts` skips the row through `NOT_YET_SHOWN_ROW_IDS`, so the Live card is exactly as before; PR-4 removes that skip together with the localized label and the dashboard row. PR-4 must add the Russian label for `mandatory-break` to the app copy (`apps/desktop/src/i18n`, `screens/app-copy.ts`) when it removes `NOT_YET_SHOWN_ROW_IDS`; PR-1 added only the English entry that the exhaustive table needs. `GAME_HISTORY_RECORDING` is unchanged.

### Fixtures

- The minor-2 corpus is in `tests/fixtures/protocol-v1/minor2`, with its own `manifest.txt` (51 payload fixtures) and `streams.txt` (12 streams). `.gitattributes` gives the new files the exact-bytes and LF rules of the other corpora. The minor-0 fixtures (`tests/fixtures/protocol-v1/*.json`, manifest, streams), the minor-1 corpus (`minor1/**`) and `tests/fixtures/protocol-v0` are byte-identical: `git status` shows no change to any of them.
- The fixtures were authored by plain text edits of the reviewed minor-1 bytes (the envelope version, the welcome's `data.minor`, and the break inserted after `gearbox`); the expectations in the manifest, the streams and the tests are hand-written, not produced by the code under test.
- The worst-case minor-2 checkpoint, `minor2/checkpoint-worst.json`, is 55,473 bytes: the minor-1 worst case (55,394) plus 79 bytes, the key `,"nextMandatoryBreak":` (22 bytes) and the widest value `{"available":false,"reason":"not-supported","unit":"min"}` (57 bytes). It fits within 65,536 (D17).
- `minor1/welcome-minor-2.json` and `minor1/ack-minor-2.json`, rejection cases for a minor-1 reader, are minor 2's own welcome and ack byte for byte.

### Tests

Expected values are written by hand from [protocol v1](../protocol/v1.md) §7 and [live telemetry fields](../live-telemetry-fields.md). REG-010 (frame parser and version), REG-009 (zero, unavailable and units) and REG-003 (hydration) are the scenarios touched; the regression registry is consolidated in the last PR, as ET-050b did.

- `tests/unit/protocol-v1.test.ts`:
  - every minor-2 manifest entry at `maxMinor: 2`, with its round trip and wrong-direction rejection; a reader at 0 or 1 refuses each minor-2 envelope and reads older ones unchanged;
  - every frozen minor-0 fixture gives a minor-2 reader the same result, and every frozen minor-1 fixture too, except the two envelopes above;
  - the break as a signed integer: 95, 0, -30 and both s32 extremes, and each unavailable reason, with zero distinct from `not-observed`;
  - bound edges: 0, -1, 119, 120 and the s32 limits accepted; 2147483648, -2147483649, 45.5, NaN, a decimal string, `null`, another unit, a missing or extra key and a `value` beside a `reason` rejected;
  - the break required exactly in a minor-2 state, on top of the gearbox;
  - the worst case: 55,473 bytes, byte-at-a-time decoding;
  - the negotiation table, hello `maxMinor` 0 to 3 against a server maximum of 0, 1 and 2, including a minor-1 offer to a minor-2 server (1, not 0);
  - the live observation still validating the minor-1 shape, which PR-4 changes.
- `tests/unit/protocol-v1-delivery.test.ts`: the 12 minor-2 streams (a minor-2 connection with cursor ACK and probe; every availability change within one connection; a minor change in a snapshot, an event or a checkpoint; an ACK or probe at another minor; a minor-2 client against minor-1 and minor-0 servers); the selected minor of each stream's connection; `V1Consumer`, `DurableAckCursor`, `AckValidator` and `computeClockMapping` at minor 2.
- `tests/unit/protocol-fuzz.test.ts`: the oracle now models minors 0 to 2 and the break (a signed integer, never a string). The maxMinor-2 readers fuzz all three corpora and the former maxMinor-1 readers keep a half campaign of their own on the minor-0 and minor-1 corpora, so a minor-2 swap stays a defect for them; each narrower reader must accept only what the wider ones accept identically; the negotiation oracle covers server maximums 0 to 2.
- `tests/unit/telemetry-core-mandatory-break.test.ts` (new): the urgency boundary table (the s32 minimum, -1, 0, 1, 59, 60, 119, 120, 121, 600 and the s32 maximum), the text table (0, 1, 59, 60, 61, 95, 119, 120, 121, 600 minutes and the maximum, clamped negatives), the normalization (values, each unavailable reason, `not-supported` below minor 2, `not-carried` under v0, other readings unchanged), and the live row (v1-only, in the `time` section after the deadline, urgency only on a current soon or due value, zero distinct from every unavailable reading, not current when stale, hidden under v0).
- `tests/unit/telemetry-core-normalize.test.ts` and `telemetry-core-boundaries.test.ts`: the v0 not-carried list gains the break, and the module list gains `mandatory-break.ts`.

Existing expectations changed in these places, each because the requirement behind it changed, never to accept a different result:

- `protocol-v1.test.ts` and `protocol-v1-delivery.test.ts` rejected a caller maximum, cursor connection minor, `AckValidator` minor and clock-mapping `maxMinor` of 2 as "not implemented"; they now use 3, since minor 2 is implemented. The ET-050b assertion `V1_MAX_MINOR === 1` moved into the new minor-2 block as 2.
- `simulator-v1-pipe.test.ts` built the scripted client's hello with `V1_MAX_MINOR`. The lockstep server compares it with the scripted client's hello, whose default offer is pinned to 1 (MB3), so the helper now says 1. This was the cause of the first full-suite failure listed below.

Mutation checks by the implementer: restoring the old negotiation expression fails the negotiation table and the fuzz oracle; making the break accept non-integers fails the fraction fixture and the bounds test. Both were reverted.

Fix round 1 (review wording and robustness, same day): the SDK header does not establish that an overdue break is negative, so the contract, the specification and the decision record now call a negative value possible but unobserved; stale comments about the highest or "either" minor were corrected (simulator tests, `scenario.ts`, `faults.ts`, `writes.ts`, the service document); `formatMandatoryBreak` now throws a clear `RangeError` for a non-integer input, with a unit test (the live view already guards it); the record no longer presents the negotiation rule as a superseded statement, because protocol v1 §4 already specified `min(offer, own)` and only the code deviated; the owner's quotes say "translated from Russian". Re-run after it with Node 24.19.0: `npm run lint` and `npm run typecheck` passed, `npm test` passed (167 files, 5,523 tests) and `npm run test:storage` passed (39 files, 460 tests; no flake).

Not run in PR-1: the native build and CTest (no native source changed), the broker, the chain tests (`test:v1-chain`, `test:cap0-chain`, `test:plugin-lock`), packaging, the packaged runtime smokes and hosted CI.
