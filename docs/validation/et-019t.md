# ET-019t: test-suite audit and Windows CI speed-up

Recorded October 17, 2026 on branch `chore/test-suite-audit`, base `main` `e08a872`. ET-019t audits the test suite against the [scenario registry](../regression-registry.md), removes dead tests, replaces sleeps that stood in for observable state, and shortens [Windows CI](../../.github/workflows/windows-ci.yml). It changes no product behavior, wire format, schema, IPC, renderer or native product source. No game was launched, and no claim about games, TruckersMP, display or performance follows.

(b) The sleep removed without a tick wait: fails the same assertion |

T9 deviates from the plan's first branch. The plan asked to remove the sleep if the server evaluates retention at the handshake. It does not: `Connection::run()` calls `store_->connect()`, which cancels the disconnect window, before its first `tick()`, so expiry is evaluated only by ticks of the listening worker before the client connects. Without a wait the case failed. No server status exposes retention, so the wait counts worker ticks through the existing console test hook instead.

Kept wall-clock assertions that check product bounds now use named constants: `startup_wait_floor_ms` (900) and `startup_wait_hang_guard_ms` (2,500) for the 1 s SDK startup wait and `unread_client_callbacks_bound_ms` (2,000) in `snapshot-transport-test.cpp`, `HELLO_TIMEOUT_MS` (300) in `simulator-v1-pipe.test.ts` and `HELD_OBSERVATION_MS` (50) in `tests/storage/journal-service.test.ts`. `tests/storage/recording-runtime.test.ts` already asserts the product constant `SERVICE_STOP_BUDGET_MS` and is unchanged. No value changed.

## Seeded journal case (C3)

The case "pages its events and intervals with cursors and marks its money totals incomplete beyond 5,000 amounts" now:

1. commits the session, `job.configured` with its `trip.open` and the first 121 fines through the real storage core (eventSeqs 2–122; the first 120 with their completeness intervals);
2. closes the database and, in one SQLite transaction with `foreign_keys = ON`, copies the core-written fine at eventSeq 122 with its `event_amounts` and `event_attributions` rows to eventSeqs 123–5,001 (4,879 copies, each identical to the template except its eventSeq) and advances the session's `committed_through_event_seq` to 5,001;
3. asserts `integrity_check` = `ok` and `foreign_key_check` = no rows inside the seeding helper;
4. reopens the file through `ws.open()` and continues as before: the core commits eventSeq 5,002.

The database triggers did not block the copy: the immutability triggers of `events`, `event_gaps` and `database_info` forbid only UPDATE and DELETE, `plugin_sessions_identity` guards only the identity columns, and the copy inserts rows and updates only `committed_through_event_seq`. The committed-fixture fallback was not needed. Every assertion is byte-identical; the diff removes only the old `const st = …` line and the 5,000-iteration loop header. Durability settings and `JOURNAL_MONEY_AMOUNTS` (5,000) are unchanged. RED: reading `JOURNAL_MONEY_AMOUNTS` amount rows instead of one more makes the case fail (`incomplete` false instead of true).

## Owner decisions of October 17, 2026

The coordinator relayed four owner decisions on the plan's open questions:

- **E1, adopted** (commit `a3ebf01`). On `pull_request` events the scaffold job runs `npm run package` and `npm run inspect:package` instead of `npm run make`, so the Squirrel distributable is not built. Pushes to `main` and every `workflow_dispatch` still run the full make. Locally, on a clean `out/`, `npm run package` wrote only `out/ETS2Telemetry Desktop-win32-x64` (no `out/make`), `npm run inspect:package` passed on it, and all six packaged runtime smokes passed from it. No CI step reads `out/make`: `inspect:package` and `Invoke-RuntimeSmoke.ps1 -Mode packaged` read `out/ETS2Telemetry Desktop-win32-x64`, the extended regressions use their own fixtures, and the evidence artifact uploads only `.local/diagnostics/package-inspection.json` from packaging.
- **E2, adopted** (commit `a3ebf01`). On `pull_request` events only the six packaged runtime smokes run; the six development smokes run on pushes to `main` and every dispatch.
- **Q2, keep.** `tests/electron/startup.spec.ts` and `npm run test:electron` stay; the test index records it as kept by owner decision.
- **U5, approved.** The coordinator adds `Windows x64 tests` to the `Protect main` ruleset (id 25232619) after the first Ready run reports it. This branch changes nothing on GitHub.

E1 and E2 use step-level conditions on `github.event_name`, not the `extended` input: the input exists only for dispatch, and the decision ties the full make and the development smokes to the event (every push to `main` and every dispatch, including `extended=false`). The job-level draft skip, the triggers, the concurrency group and the three job names are unchanged. The per-event table and the updated projection are in [docs/ci.md](../ci.md#et-019t-speed-up-october-17-2026).
