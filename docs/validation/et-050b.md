## PR-1: the protocol v1 minor-1 contract (October 25, 2026)

Based on main `43c634a`.

### Behavior

- `packages/contracts/src/protocol-v1.ts` implements minor 1. The envelope minor selects the state schema, so `state.gearbox` (B2) is required exactly in minor 1. The welcome's envelope minor must equal the minor it announces, and a hello is always version 1.0. `negotiateV1(input, {allowDurable, maxMinor = 0})` selects min(hello `maxMinor`, the server's own maximum).
- Every stateless entry point (`decodePayload`, `validateServerMessage`, `validateClientMessage`, `encodeFrame`, `FrameDecoder`, `negotiateV1`, `computeClockMapping`) defaults to minor 0. It accepts or writes minor 1 only when its caller passes `maxMinor: 1`, so every current caller behaves exactly as before.
- `packages/contracts/src/protocol-v1-delivery.ts` enforces one minor per connection:
  - `V1Consumer(durable, {maxMinor})` rejects a welcome above its `maxMinor` and any later message at another minor, and exposes the selected `minor`;
  - `DurableAckCursor.beginConnection(acked, minor)` builds ACKs at the connection minor;
  - `AckValidator(session, durable, minor)` rejects an ACK at another minor, and its `probe` method rejects a clock probe at another minor or before the checkpoint.

  Every new parameter defaults to 0.
- The live observation (`validateLiveObservationV1`, `LiveStateV1`) still validates the minor-0 state; the gearbox is projected only by PR-5.
- The plugin, broker, simulator and desktop application still negotiate minor 0. No v0, CAP0, storage, settings, IPC or native source changed, and `GAME_HISTORY_RECORDING` stays `false`.

### Fixtures

- The frozen minor-0 corpus in `tests/fixtures/protocol-v1` is byte-identical: `git diff` shows no change to any tracked fixture, manifest or stream file.
- The minor-1 corpus is in `tests/fixtures/protocol-v1/minor1`, with its own `manifest.txt` (48 payload fixtures) and `streams.txt` (11 streams). The C++ harness enumerates only the top-level directory, so it ignores the new directory until PR-3 reads it. `.gitattributes` gives the new files the same exact-bytes and LF rules as the frozen corpus.
- The layouts in `minor1/checkpoint.json` (ETS2 DAF 12-speed, 16 slots) and `minor1/checkpoint-ats-mack.json` (ATS Mack Anthem 18-speed, 22 slots) were read from the sanitized CAP-01 run9 and run4 hshifter captures in `tests/fixtures/simulator-v1/cap01`. The tables match the accepted plan.
- The worst-case minor-1 checkpoint, `minor1/checkpoint-worst.json`, is 55,394 bytes: the frozen 51,994-byte worst case plus 3,400 bytes of gearbox. The gearbox holds two `not-supported` counts, which are longer than an available 100, and 64 slots of gear −100, handle position 254 or 255 and two-digit selectors under `selectorCount` 6. It fits within 65,536 (D17).

### Tests

The expected values are written by hand from the specification and the CAP-01 tables, never generated by the code under test.

- `tests/unit/protocol-v1.test.ts`:
  - every minor-1 manifest entry at `maxMinor: 1`, with its round trip and wrong-direction rejection; the default reader refuses each minor-1 envelope and leaves each minor-0 copy unchanged;
  - every frozen minor-0 manifest entry gives the same result for a minor-1 reader;
  - the exact DAF and Mack slot tables;
  - unavailable counts and layouts, an empty layout and a zero-selector layout;
  - the worst-case size and byte-at-a-time decoding;
  - bound edges: counts 100/101, gear ±100/−101 and −0, handle position −1, selectors 63/64 under 6 selectors and 2 under 1, `selectorCount` −1, 64/65 slots, repeated gears allowed;
  - the welcome minor rule and a hello at minor 1;
  - unsupported caller maxima;
  - a live observation that still rejects a gearbox;
  - negotiation of hello `maxMinor` 0, 1 and 3 against a server maximum of 0 and 1, with `hello-wider-minor` still selecting 0 by default.
- `tests/unit/protocol-v1-delivery.test.ts`:
  - the shared stream harness takes a corpus. The minor-0 streams run unchanged at minor 0, and the eleven minor-1 streams run with a consumer and server at minor 1, including a minor-1 client against a minor-0 server. Every `C:` clock probe passes the producer-side `AckValidator.probe` check before it registers with the consumer;
  - the never-ACK control for the minor-1 streams;
  - consumer, cursor, ACK and clock-probe minor cases;
  - a minor-1 hydration checkpoint;
  - a clock-reply mapping at `maxMinor: 1`, refused at the default.
- `tests/unit/protocol-fuzz.test.ts`:
  - two v1 readers per direction. The `maxMinor: 1` payload and frame decoders start from both corpora. The default minor-0 payload and frame decoders start from the frozen corpus, with half the iterations and every version swap still a defect;
  - payload isolation counts protocols, not readers, and whatever a default reader accepts, the `maxMinor: 1` reader of the same direction must accept identically;
  - the doc-derived oracle accepts envelope minors 0 and 1, requires the welcome minor to equal the envelope minor, and checks gearbox presence and bounds by minor and negotiation for server maxima of 0 and 1;
  - for the `maxMinor: 1` readers only, the version-defect mutator no longer swaps between documented minors on kinds whose schema does not depend on the minor (event, gap, clock reply, end, ACK and probe), because that swap leaves them valid.
- A mutation check disabled the consumer's minor-change check and the ACK validator's minor check. Six of the new delivery tests then failed, including the `minor-change-checkpoint` stream; the source was restored afterwards.

### Review fix round 1

The independent review approved `a9bdb111` with five accepted findings, fixed in one commit:

1. The producer-side clock-probe minor, which the specification required but only ACKs enforced, is now `AckValidator.probe`. The shared minor-1 streams `probe-minor-0` and `old-plugin-probe-minor-1`, with the new `clock-probe-minor-0` copy, let PR-3 reproduce it.
2. The default minor-0 readers are fuzzed again, alongside the `maxMinor: 1` readers. The minor-1 corpus gains `gap.json`, which is valid at `maxMinor: 1` and refused by the default reader.
3. `computeClockMapping` takes an optional `maxMinor` that defaults to 0.
4. [Protocol v1](../protocol/v1.md) §2 states that minor 1 differs from minor 0 only by `state.gearbox`; §8's record types and the `convoy` rule now name both minors.
5. In concept.md, B6 is labelled "freshness".

Mutation checks:
- Disabling the probe minor check failed the `probe-minor-0` stream and the probe unit case. The `old-plugin-probe-minor-1` stream still failed, because a default-minor validator refuses the version first.
- Letting `version()` accept minor 1 without the opt-in failed five fuzz cases, including both default-reader payload campaigns.

The source was restored after each check.
