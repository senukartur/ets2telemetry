# ET-018: installer, upgrade and uninstall

ET-018 packages the application for distribution: installed upgrades that keep local data, and an uninstall that removes the application's own data and plugin ([concept](../../concept.md#uninstall-removes-local-data--october-16-2026)). The architect's plan of October 18, 2026 splits it into six PRs; its decisions U1–U17 and the owner decisions O1–O8 are recorded with the coordinator's authorization. This record collects each PR's local checks and the checks that stay pending. Hosted CI runs, independent review and acceptance are recorded by the coordinator. No game was launched, no installer ran on a personal machine, and no claim about real games, TruckersMP, display or performance follows.

### Decisions and deviations

- **Synthetic target instead of `data\telemetry.sqlite`.** The plan seeds `schema-v1-representative.sqlite` as `data\telemetry.sqlite`. That fixture's `database_info.purpose` is `synthetic`, and the history path refuses any other purpose (`checkPath`, `PURPOSE_MISMATCH`), so the copy would never migrate. A history-purpose copy would mean editing the fixture's contents. The harness therefore seeds the copy as `synthetic\upgrade.sqlite` and launches with `ETS2TELEMETRY_RECORDING=synthetic:upgrade`, which opens it through the same `openConnection` migration and backup path, with backups in `synthetic\backups`. It also requires that no `data\telemetry.sqlite` is created. The fixture itself is checked against `manifest.txt` before and after the copy. This proves the shared migration and backup path (`openConnection` with its verified pre-migration backup and manifest) in the installed runtime with its installed better-sqlite3. It does not prove the history-target wiring end to end: the default selection of `data\telemetry.sqlite`, the `history` purpose and the history backups folder `backups`. That wiring is unit-tested only: `tests/unit/history-storage.test.ts` ("opens the production history database under LOCALAPPDATA without waiting for it", "keeps history mode unchanged with an explicit history target"), `tests/unit/recording-policy.test.ts` ("opens history with no durable selection when the variable is unset or empty") and `tests/storage/migrations.test.ts`, which refuses the synthetic fixture under the history purpose with `PURPOSE_MISMATCH`; the runtime smokes also create a new history database at `data\telemetry.sqlite`, without a migration. The owner's first real upgrade of version 1 history remains the end-to-end check.
- **Step Jobs.** `BoundedProcess.Run` allows at most 60 s per Job, so the whole lifecycle cannot run in one Job. Every installer program and driver command runs as the root of its own Job, and the installed smokes keep their own 60 s Jobs. The `step` command waits until no process image under R is left, because Squirrel's `--updateSelf` helper outlives its parent while `BoundedProcess` gives descendants only one second after the root exits. The fixture build runs outside a Job, like `npm run make`, bounded by the step's 8 minutes.
- **Run root and evidence.** R is `$env:RUNNER_TEMP\installer-<id>`, so the installed binaries are never uploaded; the evidence is `.local/ci/installer-<id>-evidence`, already inside the uploaded `.local/ci`, so the upload paths need no new entry.
- **Copies for the read.** A read-only connection to a WAL database leaves `-wal` and `-shm` files, which would change the data root the next installer step is compared against. The reader opens copies in `R\temp`; the original is checked for sidecars before.
- **Native binding name.** The module cache names the binding by its ASAR path, `resources\app.asar\node_modules\better-sqlite3\prebuilds\win32-x64.node`, which Electron loads from `app.asar.unpacked`; the driver requires that name and the unpacked file.
- **Default scenarios.** Installed `scaffold` on 0.1.0, and `scaffold`, `plugin` and `telemetry` on 0.1.1 (`-ScenariosA`, `-ScenariosB`). The first dispatch run measures the step; trim them if the scaffold job nears 15 minutes.

### Fix round (October 18, 2026)

After the verifier's pass and the review's approval:

- **No raw machine data in the evidence.** The two `facts.json` files of the local driver check held the machine's real Steam path, the `libraryfolders.vdf` content and the process list; the verifier deleted them. The harness no longer writes facts to a file. It passes them to one driver command in `ETS2TELEMETRY_INSTALLER_FACTS`; the driver removes the variable from its own environment at once and records only `factsEvidence()`: booleans, counts, the matched product and game image names and a registered version of fixed form. The launch and verify evidence records whether the installed executable ran, not its path. A Steam library list that exists but is larger than 16 KiB or unreadable refuses the run (`STEAM_LIBRARIES_UNREADABLE`). The driver's `step` command repeats the CI signal.
- **Registry cleanup per view.** The cleanup reads the InstallLocation of each registry view and deletes the key only in a view whose own InstallLocation points into R.
- **Docs.** The CI signal is described as advisory, and the scope of the synthetic-target check is stated here, in [installer testing](../installer-testing.md) and in the REG-017 row.
- **Tests.** `installer-guard.test.ts` gained `factsEvidence` cases, the unreadable-list refusal, a run of the driver's `guard` on facts with real-looking paths, a library list and private process names (its evidence holds no drive-letter path, no list content and no unmatched process name) and a check that the harness source writes no facts file. RED: a driver guard that records the raw facts fails the driver case.

Local checks of the fix round: `npm run lint`, `npm run lint:ps` (36 files, 0 findings) and `npm run typecheck` passed; `npm test` passed with 113 files and 3568 tests; `installer-guard.test.ts` (65 tests) with `runtime-receipt.test.ts` passed five times in a row; `git diff --check` was clean. The harness still printed its plan and refused a local run with `LOCAL_RUN_REFUSED`. No installer, Setup.exe, Update.exe or `--squirrel-*` command ran locally.
