## Integrity findings fixed during implementation

A failed observation write could leave a pending loss while a delivery advanced. The recorder now freezes the event's evidence at operation entry, drains the bounded observation write/pending loss before committing the event, preserves failed evidence through retry, and refuses delivery while that loss cannot be stored. It retains the original violating value even if persistence is delayed. The real-worker regression uses the production `DurableDelivery`: while fatigue loss is held, storage reads still answer, the trip stays open and coverage/last ACK stay at 1; after release, delivery commits and ACK 2 is emitted with `isHardMode == false` and first-loss value 0. Another test injects a real SQLite before-commit failure and checks event, audit and coverage rollback together.

A cold recorder explicitly persists interruption for an already-open trip before session continuation, even with the same source/binding. A replay-origin positive path runs through the real recorder/worker in a replay-purpose database. Queued older events and redelivered openings cannot borrow current filesystem evidence. Export/SQL reconciliation preserves boolean false separately from unavailable autoparking proof. Original first-loss values survive later passing observations and appear in card/trip detail.
