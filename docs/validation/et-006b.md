Under the owner's standing delegation of October 15, 2026 the coordinator started ET-006b and adopted decisions E1–E14 ([concept.md](../../concept.md#et-006b-authorization--october-15-2026)); they are coordinator decisions and were not individually reviewed by the owner. ## Fix round 1 (review pass 1)

The verifier passed `26d4667` and independent review pass 1 approved it with six findings, fixed in `98ee2af`:

| Finding | Change | Test |
| --- | --- | --- |
| 1 (minor) The hello's durability was fixed in `open()`, before the native client sets its authority receipt, so the per-session `ACK_AHEAD_OF_STORAGE` block never applied to game sources | The hello durability and the `V1Consumer` are decided at `connect` | New `v1-ingestion.test.ts` case whose game sockets receive their authority together with `connect` |
| 2 (minor) Every hydrated checkpoint reset the backoff, so a persistent retryable storage failure reconnected about every 250 ms | The backoff restarts at a live-only connection's checkpoint and at a durable connection's first successful commit (a new optional `DurableLink.committed()` hook) | New cases: a persistent `DISK_FULL` gives 250, 500, 1000, 2000, 4000, 4000 ms and then 250 ms after a commit succeeds; a live-only checkpoint resets. The existing backoff case asserted a reset at a durable checkpoint; that requirement changed, so it now expects the 4000 ms step to persist after a checkpoint alone and the reset after the first commit |
| 3 (minor) The storage-test restart started the new worker without waiting for the old one to close the database | The new service starts only after the old client closed; work started from socket callbacks is tracked and its rejection fails the run (storage and pipe harnesses). The crash test already awaits each termination before the next spawn | Existing storage and pipe cases |
| 4 (nit) A session open completing after `stop()` could still report `active` | Ignored after `stop()` or when its connection was dropped | New `v1-durable-delivery.test.ts` case |
| 5 (nit) A test title suggested it covered commits {1, 2, 4} | Renamed; a comment states that the single FIFO cannot commit 4 before 3 and that `protocol-v1-delivery.test.ts` covers that cursor case | — |
| 6 (nit) A receive clock regression inside an observation was reported as a protocol violation | Reported as "Receive clock failure", like the freshness timer | New `v1-ingestion.test.ts` case |
