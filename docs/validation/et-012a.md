# ET-012a validation: overlay layouts and sections

ET-012a (Trello card ET-012) adds four selectable overlay layouts (Strip by default, Card, Cluster and Minimal HUD) and fourteen toggleable overlay sections, configured in the main window and saved in settings format v2. The owner approved this scope on October 15, 2026 after reviewing HTML mockups. Decisions L1–L15 are in [concept.md](../../concept.md#et-012a-authorization--october-15-2026); the behaviour is described in [the minimal overlay](../minimal-overlay.md#layouts-and-sections-et-012a), [settings](../settings.md#format-v2-et-012a) and [live telemetry fields](../live-telemetry-fields.md#overlay).

## Scope

- Settings format v2 with an `overlay` block, a pure v1-to-v2 migration, per-field fallbacks and the existing rules: a durable save before applying, quarantine of invalid files, read-only newer versions and no write at startup.
- Two narrow bridge methods, `setOverlayLayout` and `setOverlaySections`, validated in the preload and again in main.
- The overlay projection in main: each enabled, carried section formatted by telemetry-core in the displayed game's unit profile; sections without data hidden while current (speed and fuel keep a dash); the last published shape, with dashes, while not current (hidden sections stay hidden).
- Four layouts with their own CSS and lucide-react icons, per-layout window geometry inside the game's client area, and hiding when a layout does not fit. The overlay renderer stays display-only and loads no shadcn styles.
- An **Overlay** card in the main window built from shadcn components, including the new `switch` component (added with `npx shadcn@4.21.4 add switch`; `package.json` and `package-lock.json` unchanged).

Out of scope: overlay editing and dragging (ET-012b), protocol v1 exposure (ET-010c), distance driven (ET-014), multi-monitor and DPI recovery beyond the existing gates, and every protocol, native, broker, storage and trip change.

## Decisions recorded during implementation

- The store's single save path takes a change function rather than a precomputed settings value (plan step 4 described `save(next, facts)`). The new settings are computed from those in use when the write starts, so a queued unit save and a queued overlay save never undo each other.
- The strip draws its group dividers as part of the first item of each later group, so an item that wraps onto the clipped second line takes its divider with it instead of leaving a divider at the row's end. The plan mentioned dividers between non-empty groups; the visible result is the same.
- The SDK-mean caption appears only in the strip, which has no labels; the card, cluster panel and HUD already label the section ("SDK average consumption" or "SDK mean").
- The cluster draws no RPM arc at 0 rpm or while the RPM is unavailable, because a round line cap would otherwise draw a dot.
- The units card and the Overlay card share the settings view's single `saveError`; the dashboard shows it in the card whose request caused it. The `SETTINGS_SAVE_ERROR_TEXT` and `SETTINGS_STATE_TEXT` wording became neutral ("change", "settings").
- After the advisory Claude review of PR #70, main's non-current projection keeps the shape of the projection it published last instead of adding back every carried section (decision L5 amended). Before, data with no job going stale made dimmed cargo, destination and income dashes appear, and the shape depended on whether main's expiry or the overlay preload's quiet deadline fired first.

### Test changes because the requirement changed

- `settings-store.test.ts` and `main-boundaries.test.ts` expect the overlay defaults in every settings view, because `SettingsView` now carries `overlay`; saves now produce v2 bytes; the newer-version fixtures moved from version 2 to 3, because 2 is now the current format. Load facts of v1 files gain `migratedFrom: 1`.
- `settings-schema.test.ts`: v1 files are migrated instead of read as the current format, and the "no migration path to v1" case became the v1-to-v2 migration case.
- `overlay.test.ts`: the ET-008 placement expectation `{-944, 16, 300, 132}` became the strip's `{-944, 8, 928, 38}` (decision L10).
- `overlay-smoke-source.test.ts`: the observation fakes follow the new DOM contract (decision L15).
- `lifecycle-observation.mjs`: the exact saved bytes are v2 and the expected views include the overlay defaults.
- `overlay-presentation.test.ts` and `main-boundaries.test.ts`: after the L5 amendment, a non-current projection without a previous one shows only the speed and fuel placeholders (the overlay document's first delivery before any data included), and the stale table cases pass the previous current projection, so range, not observed in the fixture, stays hidden.

## Pending

- Real ETS2 and ATS sessions, single-player and TruckersMP, windowed and borderless: each layout visible above the game, click-through, no focus theft, hidden on Alt+Tab and minimize, readable at 100% and 150% scaling.
- Frame-time and resource impact of the larger transparent windows (the strip is up to 1280 × 38 DIP, the card 300 × 360), and display latency.
- Multi-monitor, mixed DPI and monitor removal beyond the existing gates.
- Settings preservation across a real installed update (ET-018).
- Sections that need protocol v1 or trip tracking (origin, distance remaining, deadline, cargo mass, company names, distance driven) stay hidden until ET-010c, the v0 retirement and ET-014.
- On a layout change of a visible overlay, main re-places the window at once while the new layout reaches the renderer through the throttled overlay delivery, so the old markup can draw in the new box for up to about 50 ms. This known transient should be watched in the real-game check.
- The card (300 × 360) and HUD (320 × 320) boxes fit the ten sections protocol v0 can fill today. Once v1 or trip data fills all fourteen sections, the last rows may be cut off by `overflow: hidden` (the review estimated about 396 px for the card); recheck the box sizes in ET-010c and ET-014. ET-012d later reserves the card, cluster and HUD heights for the enabled sections (300 × 384, 440 × 267 and 320 × 354 with every section); see [ET-012d validation](et-012d.md).

Synthetic and hidden-renderer checks establish no game, TruckersMP, display or performance claim.
