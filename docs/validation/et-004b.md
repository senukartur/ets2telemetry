## Test design

Every case drives the producer through the ET-002b C++ contract classes as an oracle. Each message is encoded with `encode()`, decoded with `decode_payload` and accepted by the client-side `Consumer`. `DurableAckCursor` stands in for the storage commit. Every ACK passes through `AckValidator` before the store releases anything. A ledger checks that a redelivered event is identical to the committed one and that a committed gap never becomes an event. Expected values are written by hand from the specification, or are the hand-written shared fixtures. Time is an explicit source-clock argument, and random cases use fixed seeds.

| CTest case | Covers |
| --- | --- |
| `store` | Fresh status, rejection of events before the first durable connection, admission, misuse rejection without effect, gap records and in-place extension, the wire status, sequence exhaustion and the `sequence-exhausted` end |
| `release` | Decision (c) as in the `ack-inside-gap-record` stream: a delta gap after an extension, an ACK inside a gap record that keeps it whole with its causes and 1,024 bytes, release point = first − 1, the reconnection checkpoint and the whole redelivered record; release at a record's last `eventSeq`; no lowering; ACK beyond the written coverage and without a connection rejected |
| `retention` | The 300,000 ms window, cancellation by a durable reconnection with `redelivered` events, events stored after the disconnect retained (S4), expiry at the deadline into one record with the expiry time (S2) and lost times from the expired events (S1), expiry of a full store and of mixed coverage without new entries, gap records never aged, the closed window and the saturated deadline |
| `overflow` | 255 events and the reserved trailing entry, newest-drop with `queueCount`, mixed-cause extension, a valid full-store status, the 63 × 16,384-byte events and the reserved 1,024 bytes, the exact byte fit, `queueCount` winning over `queueBytes`, release making room |
| `encoding` | `measure_event` bounding every envelope and equal to the worst-case one; D12 text rules including a bounded scan of an unterminated buffer; NaN, range and availability mapping; exact INT64_MIN, UINT64_MAX and u32 kilometres; documented and invalid currency; records the contract rejects becoming `encodingFailed`; a forced `std::bad_alloc` at each allocation point of an ingestion becoming `encodingFailed`, while loss recording and admission allocate nothing; a capture time before a carried time rejected, never clamped |
| `messages` | Built messages equal to the shared fixtures: `welcome`, `welcome-live`, `welcome-gameplay-unsupported`, `checkpoint`, `snapshot`, the `snapshot-live` status, all 17 `event-*` record types, `event-unavailable-occurrence`, `gap`, `clock-reply`, `end`, `end-sequence-exhausted` and `event-worst`; the OD-3 welcome; the worst-case state within 64 KiB |
| `streams` | Producer runs of the `normal`, `late-attach`, `reconnect-redelivery`/`lost-ack-reconnect`, `queue-count-overflow`, live-only then durable, `plugin-restart`, repeated delta gaps and sequence-exhaustion scenarios |
| `randomized` | Five seeds of 1,500 mixed operations (ingestion, loss runs, durable and live-only connections, partial commits, ACKs, snapshots, time jumps and expiry), then a final drain. The structural invariants run after every step. Conservation: every `eventSeq` ends committed as an event or a gap, the six loss counters sum to the `eventSeq` values covered by gaps, and each seed must exercise expiry, redelivery and all admission losses |
| `fuzz` | 3,000 seeded mutations of the `valid-client` fixtures through the contract decoder, a split client frame decoder, negotiation and `AckValidator`, with every accepted ACK releasing the store; a hand-written table of structured ACKs and their release points; a hand-written producer table of edge readings; 2,000 seeded record mutations and 300 state mutations |

The fixtures list one trailer slot, while the producer always writes ten (OD-6), so the expected checkpoint and snapshot get nine unavailable slots appended. SDK `distance.km` is a float: 151.2505f becomes 151,250.50354 m, so the test checks that value and then compares the rest of `event-job-delivered` with the fixture's 151,250.5. ### ASan root cause

With the named-local form of `available_field` restored temporarily in the working tree and the ASan test rebuilt, all nine cases failed. Each failed at the first `available_field` call, before any exception was thrown, and in a frame that holds no `std::string`. The `store` case, with line numbers of `v1-producer-test.cpp` at `7d0bf16`:

```text
ERROR: AddressSanitizer: stack-use-after-scope on address 0x002cffd823ad
READ of size 3 at 0x002cffd823ad thread T0
    #0 __asan_memcpy
    #1 `anonymous namespace'::occurred_at v1-producer-test.cpp:69
    #2 make_event v1-producer-test.cpp:74
    #3 `anonymous namespace'::store_case v1-producer-test.cpp:238
Address 0x002cffd823ad is located in stack of thread T0 at offset 253 in frame `anonymous namespace'::occurred_at v1-producer-test.cpp:68
  This frame has 5 object(s):
    [32, 68) 'compiler temporary'
    [48, 64) 'compiler temporary'
    [64, 80) 'compiler temporary'
    [80, 96) 'compiler temporary'
    [96, 104) 'f' <== Memory access at offset 253 overflows this variable
```

Line 69 assigns `available_field` results to `Field<std::uint64_t>` and `Field<std::uint32_t>` members, and `f` is the inlined function's named local. The `messages` case reported the same 3-byte read in `fixture_state`. The listed frame layout is inconsistent: objects overlap, and the access lies past every listed object. Neither suspected cause applies: no SSO string is involved (`occurred_at` creates none), and no exception had been thrown yet.

The report reproduces in this well-defined program, built with `/O2 /fsanitize=address /Zi` by MSVC 19.51.36260:

```cpp
template<class T> struct Field { T value{}; std::uint8_t state = 0; };
template<class T> Field<T> available(T v) noexcept { Field<T> f; f.value = v; f.state = 1; return f; }
struct Pod { Field<std::uint64_t> a; Field<std::uint32_t> b; };
__declspec(noinline) Pod build(std::uint64_t n) { Pod p; p.a = available(n); p.b = available<std::uint32_t>(12345); return p; }
int main(int argc, char**) { const auto p = build(static_cast<std::uint64_t>(argc)); std::printf("ok %u\n", p.b.value); return 0; }
```

It reports `stack-use-after-scope`, `READ of size 3` in `build`, with the frame objects `[32, 48) 'compiler temporary'` and `[48, 56) 'f'`. The report disappears in two variants: when `Field` gets an explicit padding member, so it has no implicit tail padding, and when `available` returns the prvalue `Field<T>{v, 1}`. The 3 bytes are the implicit tail padding of `Field<std::uint32_t>` (a 4-byte value and a 1-byte state). Conclusion: this is a false positive of MSVC 19.51 AddressSanitizer on the copy of an inlined NRVO local with tail padding, not a defect in the producer or the test. It has not been reported upstream. The prvalue form is equivalent, keeps ASan quiet without suppressing other reports, and stays.

## Deviations from the plan

- **Commit order.** The encoder header includes the store header for `ingest_event` and `Outbound`, so the records and the store are committed before the encoder. No target builds either before the CMake commit.
- **Currency per session.** Money records carry only the raw value. The encoder takes the currency of every money field from `SessionIdentity` (D11), so a fixture with documented currency is built with a separate encoder.
- **No consumer, no window.** An event stored after a retention window has ended is recorded as `retentionExpired` instead of being retained, so nothing outlives the window. Since fix round 1, an event offered before the first durable connection is rejected as misuse: the capture gate turns such events into `offline` or `noDurableConsumer` runs (OD-4). PR C must call `connect()` before opening the event gate.
- **Lost-time misuse.** `lose()` rejects one lost time without the other, and a first time after the last, instead of storing a half-available range.
- **Store-level API split.** `connect()` does not return the checkpoint status; the endpoint reads `status()` when it builds the checkpoint, so events stored in between are included.
- **`available_field`** returns a prvalue because of the MSVC AddressSanitizer false positive analyzed in fix round 1.

### Test design

Expected values are written by hand from [protocol v1](../protocol/v1.md) and [the native v1 transport](../native-transport-v1.md). The fake SDK host of the existing adapter test drives the callbacks; the test plays the v1 worker, which owns the channel, sets its gate and drains it. Captured records are checked through the ET-002b encoder and decoder, so every record must also satisfy the contract.

| Case | Covers |
| --- | --- |
| `event-channel-contract-ring` | Nothing assigned before `prepare()`; `eventSeq` in observation order; a copy independent of the caller's record; 128 slots, then `queueCount` loss with lost times, carried by the next copied record; index wrap-around over five fill and drain cycles; `prepare()` restarts the session at 1 without reallocating |
| `event-channel-contract-gate` | Gate `none` copies nothing and loses `offline`, `live` loses `noDurableConsumer`, `durable` copies; a run across gate changes keeps exact per-cause counts; a record copied while durable stays in the ring after the gate closes (OD-5 S4) |
| `event-channel-contract-loss-runs` | Lost times are the earliest and latest available observation (OD-5 S1); runs without an available time; one run across a full ring and two gate changes; a copy closes the run |
| `event-channel-contract-flush` | No run, no slot; the trailing run reaches the worker without a later record; a full ring keeps the run open and extending until a slot frees |

### Deviations from the plan

- **Build placement.** `event-channel.cpp` is compiled into `sdk-adapter` and `sdk-adapter-asan` instead of a separate library, so the adapter links no new target. It uses only the header-only v1 records, constants and the `LossCause` enumeration, so the plugin DLL links no protocol library. The adapter test now links `v1-producer` (and its ASan twin `v1-producer-asan`) for the encoding checks and the drain into the store; the event-channel test links `sdk-adapter`.
- **Macro guard.** `pipe-security.hpp` includes `<windows.h>` without `NOMINMAX` before `sdk-adapter.hpp`, and the frozen `protocol-v1.hpp` calls `std::numeric_limits<...>::max()`. `event-channel.hpp` hides the `min`/`max` macros with `push_macro`/`pop_macro` while it includes the v1 headers.
- **Multi-cause loss runs.** A gate change can occur inside one run, so a run carries one count per cause instead of a single cause. The worker records it with one `lose()` per nonzero cause in a fixed order; the parts merge into one gap record with exact counts and the run's lost times. The reference drain loop lives in the adapter test (`V1Worker`) because a production copy would link the store into the adapter; PR C moves it into the endpoint.
- **State values from v0 readings.** The v1 `StatePod` takes each channel's availability from the v0 reading and its value divided by the v0 factor (1, 100 or 1,000). An SDK float times such a factor is exact in double, so the division restores the SDK value exactly, and the channel callback stays unchanged.
- **Configuration copy flag.** The slot copies the configuration only after a configuration boundary, tracked by a pending flag rather than a revision comparison: a contended publication keeps the copy pending, and the saturating v1 revision cannot hide a change.
- **v1 revision.** It counts job and truck callbacks and the trailer callbacks that emit a record. It saturates at `UINT64_MAX` instead of retiring the source, because retiring would change v0 behavior.
- **Callback moment.** `occurred` describes the state after the callback updated it, so `simulation.started` carries `running`. The owner approved this rule on October 15, 2026; see fix round 1 below. A gameplay callback without an info pointer or id cannot be typed and gets no record; v0 still counts it as a callback failure.
- **Initialization.** `initialize()` also try-locks the v1 slot and returns `not_now` when a worker holds it, like the two v0 locks. Since fix round 1 it takes all three locks before any reset and detaches a channel left from the previous session.
- **Test pacing.** The concurrency case releases one frame of 64 observations at a time, so that the stalls deterministically overflow the ring; both threads still access the ring concurrently within each frame. The adapter test accepts `v1-capture`, `v1-state`, `v1-nonblocking`, `v1-isolation`, `v1-drain` and `v1-session` as arguments for local diagnosis; CTest runs all cases in one entry.

### Deviations from the plan

- **An extra `invariant` case.** The `rejected` retirement has its own case beside `exhaustion`, so the plan's sixteen names plus `invariant` give seventeen console cases.
- **Write bursts.** A loop iteration may issue up to 32 writes, but only while each completes at once; there is never more than one write in flight, and a pending write keeps its 1 s deadline. Under a callback flood each iteration's drain measures every drained event, and one write per iteration then lagged far behind the drain.
- **Retained items at shutdown.** Within the 250 ms `end` budget, retained items the client has not received are written during the first 150 ms, then `end`. The plan names only the `end` budget; this is best effort and never waits for an ACK (D14).
- **The server owns the channel and a fresh store per plugin session.** `Server::prepare()` returns the channel for `attach_events()`, so `sdk-exports.cpp` holds no channel itself (holding it by value triggers C4324).
- **Window mapping.** `v1::window_field` repeats the conditions of v0 `current_window`, which needs a full v0 snapshot; the `handshake` case checks that both agree.
- **Lock hold.** The "lock hold" test hook is a `v1-tick` hook point on the existing `transport_test_hook`: it holds the worker at the start of an iteration, so the ring fills while callbacks continue.
- **ASan-specific test bounds.** Private-byte growth is asserted in Release only, because AddressSanitizer's quarantine and shadow memory dominate it. DLL-owned threads are counted by start address only where the start address lies in the module (Release); under ASan the runtime intercepts thread creation, so the process thread count is the evidence.
- **One sentence outside the owned documents.** [The SDK adapter](../sdk-adapter.md#protocol-v1-capture-et-004b) said that the production DLL attaches no channel; that is no longer true and was corrected.
- **Linking.** The three transport libraries now link `v1-producer` (and `v1-producer-asan`), so the production DLL contains the protocol v1 encoder and store.
