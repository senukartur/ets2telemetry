## Independent review correction round

The coordinator froze the first candidate as
`7873386596fe7706402ab38599464a57e13b7467` and reported its full 239-test pass.
Independent review nevertheless found three P2 blockers: reordered equivalent
configuration keys fabricated an offline transition; arbitrary unused scenario
properties survived cloning; the CLI checked path metadata before a separate
unbounded read. Passing the original corpus did not establish these invariants.
The reviewer's file-limit reproduction injected inconsistent metadata/read bytes
in memory; it was not an actual concurrent filesystem mutation.

New tests against unchanged `7873386` implementation produced an actual red
run: 36 tests, 31 passed and five failed. The key-order case reported two
transitions instead of one; undeclared 3 MiB root, step and reading properties
were accepted; and the CLI exited successfully after a real temporary fixture
grew beyond the cap following its metadata query. Raw output is
`.local/et005a-checks/review-red.txt`; the baseline CLI build is recorded in
`review-red-build.txt`. These failures were reproduced before source fixes.

The filesystem regression appends actual bytes to an owned temporary file at
a deterministically intercepted stat/open boundary. It is not an uncontrolled
simultaneous external writer test. The retained regression builds current CLI
source into its own temporary directory, then grows the fixture after opening,
requiring overflow rejection and no stdout. It does not rely on a cached bundle
or a root build occurring before the fast test suite.
