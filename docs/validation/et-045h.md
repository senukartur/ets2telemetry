## Shortcut migration

Squirrel (pinned commit `eef37460ae`) names a shortcut after the executable's ProductName and writes or removes only the current name, so the old `ETS2Telemetry Desktop.lnk` would stay beside the new one after an update and after an uninstall. `apps/desktop/src/legacy-shortcuts.ts` and the hooks in `apps/desktop/src/squirrel-events.ts` handle it ([releases](../release.md#shortcut-migration-et-045h)):

- `--squirrel-install` (any Setup, also a newer one over an install) and `--squirrel-updated` (`Update.exe --update`) delete the owned old names on the Desktop and in `Programs\Artur Sianiuk` after `--createShortcut` succeeded and only where the new name exists, within 1 s beside the deferral disarm (worst case still 12 s inside Squirrel's 15 s).
- `--squirrel-uninstall` deletes them after `--removeShortcut`, without requiring a new one; the receipt's `shortcuts` is `failed` when one could not be deleted.
- Ownership: no AUMID or Squirrel's `com.squirrel.ETS2TelemetryDesktop.ETS2TelemetryDesktop`, and a target of the install root's stub, an `app-<version>` executable, or `Update.exe --processStart ETS2TelemetryDesktop.exe` (optionally `--process-start-args <one argument>`); a plain file of at most 64 KiB. Shortcuts are read with Electron's `shell.readShortcutLink`.
- Not touched: pins, the company folder, other files and the autostart Run value. A Start Menu redirected apart from Roaming AppData is not found.
