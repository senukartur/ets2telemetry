**Failures during development.** Each failure below was fixed before the runs above:

- A seeded random stream in `trip-reducer-replay.test.ts` found a reducer bug. A not-connected interval queued at a reconnection kept the monotonic bounds of its session. A plugin restart before the next commit then had the new session's first commit carry them, but storage registers source clocks under the committing session (T11). The fix strips the bounds of queued intervals when a new session of the game starts. The deterministic case "a queued not-connected interval of an earlier session drops its monotonic bounds…" reproduces it: it fails with the fix disabled and passes with it.
- Test-construction errors: a miscounted eventSeq in one case, a gap built before the events that precede it, and a hard-coded reconnect coverage. These were corrected in the tests; no expectation was changed to match reducer output.

## Expectation sources

Expected effects and rows are written by hand from [trips](../trips.md), T1–T20 and the CAP-01 observations O1–O11 ([CAP-01a validation](cap-01a.md)); none is copied from reducer output.

- Every case in `trip-reducer.test.ts` names its basis: an observation O1–O11, `concept-2026-10-13/14`, or `synthetic-inference`.
- Trip UUIDs in the expectations come from an independent `node:crypto` implementation of the T4 derivation.
- SHA-256 expectations are the NIST example vectors, plus parity with `node:crypto`.
- O-tagged cases are synthetic sequences shaped after the text observations. No capture bytes are committed, so CD-7 does not apply.
