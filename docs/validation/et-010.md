# ET-010 live telemetry validation

## Scope and authorization

The coordinator started ET-010 on October 15, 2026 under the owner's standing autonomy of that day and adopted decisions N1–N16 ([concept.md](../../concept.md#et-010-authorization--october-15-2026)). The owner did not review those decisions individually. ET-010 is three packages: ET-010a, ET-010b and ET-010c.

This record covers **ET-010a** on branch `feat/live-telemetry-normalization`, based on `0bece49`:

- pure modules in [packages/telemetry-core/src](../../packages/telemetry-core/src): unit conversion, display profiles, readings, v0 and v1 normalization, formatting, derived values and step primitives, and the live view model;
- Vitest `telemetry-core-{units,normalize,format,derived,live-view,boundaries}.test.ts` in [tests/unit](../../tests/unit);
- the [field catalogue](../live-telemetry-fields.md) and the dated documentation entries.

`package.json`, `package-lock.json`, `tsconfig.json`, `vitest.config.mts`, `packages/contracts/**`, `tests/fixtures/**`, `apps/**`, `native/**`, `tools/**` and `.github/**` are unchanged. No application code calls the new modules yet; ET-010b connects the dashboard.

## Test provenance

The tests read the shared protocol v0 and v1 fixtures without changing them. Expected values were written by hand from the fixture bytes, the protocol specifications, the SDK 1.15 headers (heading direction in `scssdk_value.h`) and the exact unit definitions, never produced by the code under test. Rounding-boundary cases straddle each half-step on both sides and avoid exact binary ties.

## Fix round 1

Independent review pass 1 requested changes. They were fixed in new commits on top of `34b4e6b`:

| Finding | Fix | Commit |
| --- | --- | --- |
| `fuelStep` reported decreases of up to 0.01 L as `unchanged`, so ordinary 1 Hz and 20 Hz consumption was lost | Every decrease is `consumed` with its exact amount; the 0.01 L band applies to refuel detection only, and a small increase is `unchanged` with its exact `increaseLiters`. The caller contract is in the [field rules](../live-telemetry-fields.md#step-primitives-reg-008). The old "changes within 0.01 L are unchanged" test was replaced because the requirement changed | `a7d09cd` |
| A provided fuel capacity of 0 gave the fuel level `not-supported` | It is `invalid`: zero is not a valid denominator. The changed expectation follows that requirement change | `a7d09cd` |
| v0 rows such as the truck plate, source city, cargo mass, market and deadline became visible when the parent truck or job reading was missing or stale | Carriage is a static per-protocol table (`V0_CARRIED_FIELDS`); v1 carries every field | `004f018` |
| A current v1 state with only empty trailer slots showed a permanent not-observed row, and invalid slots were dropped | Such a state is the `absent` row `none` (reason `no-trailer`); invalid slots show `(invalid)`, and only invalid slots make the row `invalid` | `004f018` |
| The boundary test did not reject Node globals or triple-slash references, and its self-test did not run the real rules | The scan strips comments and string contents and rejects `process`, `Buffer`, `__dirname`, `__filename`, `global`, `require` and `/// <reference>`; the self-test runs `violations()` on a known-bad input for each rule | `2fc93bf` |
| Documentation | The ATS note cites `amtrucks/scssdk_telemetry_ats.h` lines 63–65; the REG-008 registry row is Partial; the technical-debt header allows labelled coordinator decisions | this documentation commit |

## Remaining verification

ET-010a is synthetic evidence only. It establishes no game, TruckersMP, display or performance behavior. Pending:

- Real-source dashboard checks in ETS2 and ATS, single-player and TruckersMP, against the in-game dashboard and job offer: speed including reverse, gear in automatic and reverse, RPM, fuel, capacity, range, SDK average consumption, odometer, game time, cargo, destination, planned distance and expected income (ET-010b).
- ATS US customary units, paused and menu-only states, late attach in the middle of a job, and electric trucks.
- Route remaining with and without a navigation route (ET-010c).
- Bobtail versus a coupled trailer, including late attach: whether every empty v1 slot really means no trailer attached.
- The provisional step thresholds: refuelling and fuel noise, teleport, ferry and train jumps.
- Runtime currency, which is still SDK-documented or unknown.
- Whether the ATS SDK average consumption is mostly static at runtime, as the pinned header `amtrucks/scssdk_telemetry_ats.h` (lines 63–65, "as of v1.00") documents, and whether ETS2, whose header states no such limitation, behaves differently (the `ats-mostly-static` note).
- Renderer cost of building the view at 20 Hz.
