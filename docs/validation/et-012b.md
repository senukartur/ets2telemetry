# ET-012b validation: overlay edit mode and position persistence

ET-012b (Trello card ET-012, package "Edit mode and position persistence") adds an explicit overlay edit mode in which the user drags and scales the overlay and then deliberately returns to the click-through driving mode. The position and scale of each layout are saved in settings format v3 and restored after a restart. The coordinator started the package under the owner's standing autonomy of October 15, 2026; decisions M1–M13 are in [DESIGN-DECISIONS.md](../../DESIGN-DECISIONS.md#et-012b-authorization--october-15-2026). The behaviour is described in [the minimal overlay](../minimal-overlay.md#edit-mode-et-012b) and [settings](../settings.md#overlay-placements-and-edit-mode-et-012b).

## Scope

- Settings format v3: `overlay.placements` with the `x`, `y` (fractions of the client area's free space) and `scale` (0.5–2) of all four layouts, a pure v2-to-v3 migration (and the v1-to-v3 chain), per-placement fallbacks without clamping, exact canonical bytes and the existing rules: a durable save before applying, quarantine of invalid files, read-only newer versions and no write at startup.
- Placement-aware geometry (`overlayBounds`, `placementFromBounds`); the default placements reproduce the ET-012a anchors exactly. The scale sizes the window and is the overlay document's zoom factor.
- A main-owned edit mode in the overlay controller: shown and interactive only while the dashboard or the overlay is focused (150 ms grace for losses) and the game is not in front; hidden before it becomes click-through again; never a taskbar tab; native drag through `app-region: drag` with a snap inside the client area after the drop.
- Four fixed-shape IPC channels (`overlay-edit:begin`, `overlay-edit:set-scale`, `overlay-edit:reset`, `overlay-edit:finish`) from the trusted dashboard frame only, `AppState.overlayEdit`, and the layout channel refused while editing. Done/Enter saves through the shared settings queue after leaving edit mode; Cancel/Esc and every dashboard or overlay retirement or exit discard without writing.
- A **Position and size** block in the dashboard's Overlay card with existing shadcn `Button`s only. The overlay renderer receives only a display-only `editing` flag; it loads no shadcn styles and its bridge is unchanged.

Out of scope and deferred: multi-monitor placement, mixed DPI, monitor removal and off-screen recovery; an overlay visibility on/off setting (concept.md §6 lists "visibility" among the persisted overlay settings; it is not in the ET-012b brief and stays open on the ET-012 card); a preview while the game is minimized; protocol, native, broker, storage, trip and PowerShell changes. `package.json`, `package-lock.json`, `scripts/ci/RuntimeReceipt.ps1` and the lint configuration are unchanged.

## Decisions recorded during implementation

- **The lifecycle smoke saves no edited placement (deviation from plan step 11).** The plan asked run A to save an edited strip scale of 1.25 after the unit save and run B to restore it. `RuntimeReceipt.ps1` requires exactly one `SETTINGS_SAVED` row in run A (`Test-LifecycleSettingsReceipt`, with a negative "second save" case in `runtime-receipt.test.ts`), and the plan keeps that script unchanged. Run A therefore still saves only the units, now as exact v3 bytes with the default placements, and run B checks the restored (default) placements, driving mode after the restart and the overlay zoom factor of the saved scale (1). An edited, non-default placement is saved by the overlay smoke (card at scale 1.5), and its restore after a restart is covered by unit tests: `settings-store.test.ts` loads a v3 file with moved placements, and `main-boundaries.test.ts` creates the overlay window at the saved scale's size with that zoom factor and re-applies it after each load.
- `placementFromBounds` takes the previous placement instead of only the scale (plan M3), because "keeps the previous fraction" needs it.
- The edit state's `too-large` covers only a layout that does not fit the client area at its scale. A box that fits the client area but not a display, or a conversion failure, reports `waiting-for-game`, like a missing game window.
- The scale is applied as the zoom factor whenever the scale in use changes (the draft while editing, the saved one otherwise), even while the overlay is hidden, and not only when it shows. Without that, an edited scale saved while no game window exists would not reach the zoom factor until the next show.
- A saved placement that arrives while editing (for example after a unit or section save) is remembered; the draft stays until edit mode ends. Should a different layout ever arrive while editing, the edit is cancelled (main refuses layout changes while editing, so this is defensive).
- With a diagnostic directory, main records the timeline rows `OVERLAY_EDIT_STARTED`, `OVERLAY_EDIT_FINISHED` (`outcome`) and `OVERLAY_EDIT_CANCELLED` (`reason`); default logs are unchanged.
- After the independent review of `510b44f` (fix round 1): minimizing the dashboard cancels edit mode without writing, like closing it to the tray (added to M5), because edit mode keeps the driving overlay hidden and a user who minimizes the dashboard and drives would otherwise have no overlay for the whole drive. When the overlay document is retired, main now marks it not loaded before cancelling the edit, so the retired document is never shown for driving in between. The documentation now states that the overlay can cancel an edit by retiring its subscription, and that the lifecycle smoke restores the default placements.

### Test changes because the requirement changed

- `settings-schema.test.ts` and `settings-store.test.ts`: version 3 is now the current format, so the current-format cases use v3 inputs and expect the default placements, saves produce v3 bytes, and the newer-version fixtures moved from version 3 to version 4. A v2 file now loads with `migratedFrom: 2`, so the ET-012a case "loads a v2 overlay block and reports no migration" became the v2 migration case, and a v3 case reports no migration. Fallback lists for a missing or non-object overlay block gain `overlay.placements`.
- `overlay-sections.test.ts`: `DEFAULT_OVERLAY_SETTINGS` now includes the default placements.
- `main-boundaries.test.ts`: `SettingsView.overlay` carries `placements`, so the fixture's overlay settings do; `AppState` carries `overlayEdit`, so the exact application-state expectations include `{active: false}`. The fake window and web contents gain the methods main now calls (`isFocused`, `setMovable`, `setSkipTaskbar`, `getBounds`, `setZoomFactor`).
- `overlay-preload.test.ts`, `overlay-view.test.ts`, `overlay-sections.test.ts`: `OverlayPresentation` carries `editing`, so the fixtures and the exact stale expectations include it.
- `overlay.test.ts`: the controller mock gains `setSkipTaskbar`, `setMovable` and `webContents.setZoomFactor`; no expected value changed.
- `preload-recovery.test.ts`, `runtime-smoke.mjs`, `native-smoke.mjs`, `startup.spec.ts`: the dashboard bridge key lists include the four appended methods.
- `lifecycle-observation.mjs`: the exact saved bytes are v3 and the expected views include the default placements.

## Pending

- Real ETS2 and ATS sessions, single-player and TruckersMP, windowed and borderless: enter edit mode, drag and scale over the game, Done, Cancel, Enter and Esc, and the restored position and scale after a restart.
- Whether the game's window reports stay fresh and non-minimized while the game runs in the background behind the dashboard; edit mode depends on them. If they do not, edit mode always reports waiting for the game and needs a separate fix.
- Focus transitions: a click from the dashboard onto the overlay starts a drag without flicker; Alt+Tab to the game during edit mode hides the overlay; afterwards driving mode is click-through, steals no focus, shows no taskbar tab and stays above the game.
- Keyboard focus after a click on the drag region (Enter and Esc reaching the overlay), Alt+Space, and no menu on a right click.
- `app-region: drag` on the sandboxed, transparent, zoomed overlay window has not been tried on hardware.
- Readability at scales 0.5–2.0 and at 100 % and 150 % display scaling.
- The edit overlay can stay visible over another application for up to 150 ms after the user switches to it (the focus grace); confirm this is not noticeable.
- Deferred: multi-monitor placement, mixed DPI, monitor removal and off-screen recovery; display latency, resource use and frame-time impact.
- Settings preservation across a real installed update (ET-018). Going back to an ET-012a build reads a v3 file as `newer-version` (read-only defaults); this downgrade behaviour is accepted (M2).

Synthetic and hidden-renderer checks establish no game, TruckersMP, display or performance claim.
