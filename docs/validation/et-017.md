ET-017 implements the owner's [silent plugin installation](../../concept.md#silent-plugin-installation--october-12-2026) decision of October 12, 2026 in six PRs; see [game plugin setup](../plugin-setup.md). ## PR-3: atomic installer and install registry (October 17, 2026)

Branch `feat/et-017-plugin-installer`, based on `883f452` (PR-2 under review, merged with `main` `5e98b97`, which contains PR-1); implementation commit `1ac8449`. PR-3 adds three modules in `apps/desktop/src/plugin-setup/`:

See [algorithm](../plugin-setup.md#algorithm) and [install registry](../plugin-setup.md#install-registry).

### Deviations from the plan

- **Pending intent fields.** A pending intent also records `source`, `appVersion` and `createdPluginsDirectory`, beside P8's `{op, game, root, temp, fromSha256, toSha256, startedUtc}`. Recovery needs them to record an install whose rename completed before an interruption, with its source, version and created-folder flag.
- **Folder creation order.** A missing `plugins` folder is created after the pending intent is written (P8 step 6), not at step 2. Otherwise a failed intent write would leave a created folder that no record names, and P8 says the folder must stay untouched when that write fails. The intent records that this run creates the folder.
- **Read-only removal.** Removal also refuses a read-only target (`READ_ONLY_FILE`). Node's `unlink` clears the read-only attribute before it deletes, and P8 step 5 forbids clearing it.
- **Rename over an open file.** P7 expects `EBUSY` for a sharing lock. Measured on October 17, 2026, Windows refuses a rename over a target that another process holds open without delete sharing with `ERROR_ACCESS_DENIED`, which Node reports as `EPERM`. Such a lock is therefore `TARGET_LOCKED` at once, without retries. `EBUSY` from a sharing violation, for example while reading a target held with `FileShare.None`, is still `TARGET_LOCKED`, and the rename still retries `EBUSY` as P8 requires.
- **Quarantine timing.** The registry quarantines an invalid file at its first write, not at load, so that loading never writes, as in the settings store.
- **Registry bounds.** A write that would exceed the 16-install or 16-intent bound is refused with `REGISTRY_UNAVAILABLE`; no entry is evicted.

### Isolation

- Every unit case runs on fake game roots and a fake registry folder under the guarded temporary root, and fails if any path outside it was requested.
- The sharing-lock cases start a Windows PowerShell 5.1 child that opens only the fake target, through an environment variable, and is ended after each case.
- The ACL case asserts that the folder lies inside the guarded root before it runs `icacls /deny` for the current user's SID. It removes the deny in `finally` and checks that `icacls` no longer lists a deny entry.
- The image lock check runs the tests-only fake SDK host from the native build, with transport folders in its temporary root. Before it starts, it requires that `tasklist` shows no ETS2, ATS or TruckersMP process.
- `tasklist` showed no `eurotrucks2.exe`, `amtrucks.exe` or `truckersmp*` process before each plugin-lock run below.
- No real Steam library, game folder, `%LOCALAPPDATA%\ETS2Telemetry` or registry key was read or written.
