# ET-017: game plugin setup

ET-017 implements the owner's [silent plugin installation](../../concept.md#silent-plugin-installation--october-12-2026) decision of October 12, 2026 in six PRs; see [game plugin setup](../plugin-setup.md). The coordinator adopted the architect's decisions P1–P20 under the owner's standing delegation of October 15, 2026. The owner agreed explicitly to P11 (excluding a game in the application removes its plugin; closing a game never does) and P12 (no elevated helper) on October 17, 2026, and did not review the other decisions individually. This record collects each PR's local checks and the checks that stay pending. Hosted CI runs, independent review and acceptance are recorded by the coordinator. No game was launched for any record below, and no claim about real Steam installations, games, TruckersMP, display or performance follows.

## PR-1: bundle the plugin DLL with a hash manifest (October 17, 2026)

Branch `chore/et-017-plugin-bundle`, base `main` `1bc41fe`, implementation commit `35ce61b`. Local environment: Windows 11 Home 10.0.26200, Node 24.19.0 and npm 11.17.0, CMake 4.3.1-msvc1 with the `Visual Studio 18 2026` generator.

### Changes

- `scripts/stage-native-plugin.mjs` runs in `npm run build` after the native broker build. It configures `native/telemetry-plugin/build` with `-A x64` only when the tree has no `CMakeCache.txt`, builds the `ets2telemetry-plugin` target in Release and writes the DLL with `plugin-manifest.json` to `.local/package-native/telemetry-plugin`.
- `scripts/plugin-bundle.mjs` (types in `plugin-bundle.d.mts`) holds the manifest writer, `verifyPluginBundle` and `verifyPluginBundleAgainstTree`.
- `native/telemetry-plugin/released-plugins.json` is the tracked, empty released-hash list.
- Forge maps `.local/package-native/telemetry-plugin` to `resources/telemetry-plugin`. `scripts/inspect-package.mjs` verifies it and records `nativePlugin` in `package-inspection.json`.
- `scripts/source-inputs.mjs` adds `scripts/stage-native-plugin.mjs` and `scripts/plugin-bundle.mjs` to the build fingerprint.
- Windows CI configures the plugin tree with `-G 'Visual Studio 17 2022'` before `npm run build`, so the stage script reuses it ([ci](../ci.md#et-017-plugin-bundle)).

No application code reads the bundle, and nothing discovers a game or writes into a game folder. No wire, schema, IPC, settings, lockfile or native source changed.

## PR-2: Steam discovery and manual game folders (October 17, 2026)

Branch `feat/et-017-steam-discovery`, base `main` `1bc41fe`. PR-2 adds read-only, injectable modules in `apps/desktop/src/plugin-setup/`: `vdf.ts`, `steam-discovery.ts`, `steam-registry.ts`, `game-folder.ts`, `game-processes.ts` and the shared `fixed-program.ts`. Nothing calls them from main yet. The test helpers `tests/shared/guarded-fs.ts` and `tests/shared/fake-steam.ts` confine every test to fake roots in a temporary folder.

### Isolation

- Every discovery and folder test reads through the guarded file system and fails if any path outside its temporary root was requested, also when the code under test caught the refusal.
- The one real registry run writes a Cyrillic SteamPath into `HKCU\Software\ETS2Telemetry-Test-<uuid>` and reads it with the fixed script, whose key names are replaced by that test key; the recorded scripts are asserted not to name Valve's keys. The key is deleted after the test; after the runs below, no `ETS2Telemetry-Test-*` key remained under `HKCU\Software`.
- The one real `tasklist` run only lists processes.
