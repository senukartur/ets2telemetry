# ET-017: game plugin setup

ET-017 implements the owner's [silent plugin installation](../../concept.md#silent-plugin-installation--october-12-2026) decision of October 12, 2026 in six PRs; see [game plugin setup](../plugin-setup.md). The coordinator adopted the architect's decisions P1–P20 under the owner's standing delegation of October 15, 2026. The owner agreed explicitly to P11 (excluding a game in the application removes its plugin; closing a game never does) and P12 (no elevated helper) on October 17, 2026, and did not review the other decisions individually. This record collects each PR's local checks and the checks that stay pending. Hosted CI runs, independent review and acceptance are recorded by the coordinator.

## PR-1: bundle the plugin DLL with a hash manifest (October 17, 2026)

Branch `chore/et-017-plugin-bundle`, base `main` `1bc41fe`, implementation commit `35ce61b`. Local environment: Windows 11 Home 10.0.26200, Node 24.19.0 and npm 11.17.0, CMake 4.3.1-msvc1 with the `Visual Studio 18 2026` generator.

### Changes

- `scripts/stage-native-plugin.mjs` runs in `npm run build` after the native broker build. It configures `native/telemetry-plugin/build` with `-A x64` only when the tree has no `CMakeCache.txt`, builds the `ets2telemetry-plugin` target in Release and writes the DLL with `plugin-manifest.json` to `.local/package-native/telemetry-plugin`.
- `scripts/plugin-bundle.mjs` (types in `plugin-bundle.d.mts`) holds the manifest writer, `verifyPluginBundle` and `verifyPluginBundleAgainstTree`.
- `native/telemetry-plugin/released-plugins.json` is the tracked, empty released-hash list.
- Forge maps `.local/package-native/telemetry-plugin` to `resources/telemetry-plugin`. `scripts/inspect-package.mjs` verifies it and records `nativePlugin` in `package-inspection.json`.
- `scripts/source-inputs.mjs` adds `scripts/stage-native-plugin.mjs` and `scripts/plugin-bundle.mjs` to the build fingerprint.
- Windows CI configures the plugin tree with `-G 'Visual Studio 17 2022'` before `npm run build`, so the stage script reuses it ([ci](../ci.md#et-017-plugin-bundle)).

No application code reads the bundle, and nothing discovers a game or writes into a game folder. No wire, schema, IPC, settings, lockfile or native source changed.

### Deliberate failures (RED)

Each fault was made after a passing package, checked and then reverted; `inspect:package` passed again afterwards.

| Fault | `npm run inspect:package` result |
| --- | --- |
| One byte of the packaged `resources/telemetry-plugin/ets2telemetry-plugin.dll` flipped | Failed: `Plugin DLL hash differs from its manifest` |
| One byte of the staged `.local/package-native/telemetry-plugin/ets2telemetry-plugin.dll` flipped, then `electron-forge package` without a rebuild | Failed: `Plugin DLL hash differs from its manifest` |
| A comment appended to `native/telemetry-plugin/src/sdk-exports.cpp` after packaging | Failed: `Plugin bundle built from stale plugin sources` |
| An entry added to `released-plugins.json` after packaging | Failed: `Plugin bundle known hashes differ from the released plugin list` |

Mutations of `scripts/plugin-bundle.mjs` that each dropped one check (the x64 machine check, the DLL link check, the plugin-source comparison, the `known` comparison, the manifest hash comparison, the strict-key check and the local-build comparison) each failed at least one case of `plugin-bundle-stage.test.ts`; the file was restored and all 16 cases pass.

After the reverted source edit, the rebuilt DLL had a different SHA-256 from the first build of the same sources. This is the non-reproducible MSVC output that the released-hash list exists for ([released plugin list](../plugin-setup.md#released-plugin-list)).
