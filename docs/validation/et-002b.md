## Fixture provenance

Every fixture is synthetic (`origin: synthetic`) and contains no capture strings, plates or player data. Field names and types follow the CAP-01 observations and the pinned SDK 1.15 headers. Payload files were composed from hand-written templates by a throwaway script that does not import the implementation under test. The expected results in `manifest.txt` and `streams.txt` were written by hand from the specification. Two fixture mistakes found by the first test run were corrected in the fixtures, not in the expectations: `snapshot-live` lacked `durable: false`, and a test used an end marker whose acknowledgement exceeded the delivered coverage (the new `end-early` fixture replaced it there).

## Deviations from the architect plan

- **Last assignable `eventSeq`.** The plan listed "a max-uint64 eventSeq" as accepted. A uint64 `nextEventSeq` cannot follow an event numbered 18,446,744,073,709,551,615, so the contract makes 18,446,744,073,709,551,614 the last assignable `eventSeq` (`MAX_EVENT_SEQ`). The max-uint64 value stays accepted for message `seq`, monotonic times and money, and `event-seq-uint64-max.json` is rejected.
- **Game-mode invariant.** "Unknown pairs with none" is implemented as: `unknown` if and only if method `none` and confidence `none`.
- **Game mode pointer in concept.md.** As the plan requires, a dated one-line pointer was added at the end of the existing "Game mode as a trip attribute" section. No earlier text was changed.
