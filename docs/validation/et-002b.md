## Fixture provenance

Every fixture is synthetic (`origin: synthetic`) and contains no capture strings, plates or player data. Field names and types follow the CAP-01 observations and the pinned SDK 1.15 headers. Payload files were composed from hand-written templates by a throwaway script that does not import the implementation under test. The expected results in `manifest.txt` and `streams.txt` were written by hand from the specification. Two fixture mistakes found by the first test run were corrected in the fixtures, not in the expectations: `snapshot-live` lacked `durable: false`, and a test used an end marker whose acknowledgement exceeded the delivered coverage (the new `end-early` fixture replaced it there).

### Independent review round 1 (October 14, 2026)

An independent review of `3bbfd1e` requested changes. The coordinator accepted every finding, and the follow-up commits address them:

- **ACK cursor against the producer rule (major).** `DurableAckCursor.ack()` could repeat a commit whose ACK was lost before the new connection had redelivered it, which `AckValidator` must reject. The cursor now keeps per-connection marks: it sends min(contiguous committed, highest `eventSeq` received on this connection) and only above the last ACK sent on this connection, both starting at the checkpoint's *A*. §10 states the consumer and producer rules side by side. The `lost-ack-reconnect` and `retention-expired-ack` streams and three cursor-to-validator unit cases failed against the previous cursor behavior (5 failures in a local red run) and pass now. The earlier unit expectation that a reconnect at *A* = 5 immediately acknowledged 7 encoded the defect and was corrected.
- **Full retained store (minor).** §9 now reserves one entry and 1,024 bytes (`GAP_RECORD_BYTES`) for a trailing gap record, extends that record in place with mixed causes, never evicts gap records by age and converts expired events into gap coverage without adding entries. The status validator rejects a full store without gap bytes. New fixtures: `snapshot-full-store`, `status-full-without-gap-bytes`, `status-bytes-limit`, `gap-worst` (854 bytes). Gap-only stores in existing fixtures now account 1,024 bytes.
- **Fixtures isolating one rule (minor).** `wrong-unit-planned-distance`, `welcome-duplicate-event-type`, `invalid-utf8`, `overlong-utf8` and `deep` now each carry exactly one defect inside an otherwise valid message, and `bom` and `malformed-number` were added. A throwaway local check, not committed, confirmed that each of these, `game-mode-unknown-with-module` and the two new status fixtures becomes valid when its one defect is repaired.
- **Live-only ACK rule (minor).** `AckValidator` now takes the welcome's `durableEvents` grant and a `checkpoint()` call; it rejects any ACK from a live-only client and any ACK before the checkpoint. The `live-only-ack` and `ack-before-checkpoint` streams are rejected by contract code; the stream harness no longer throws protocol errors itself.
- **Clock probe deadline (minor).** A late reply is accepted, ends the outstanding probe and yields no mapping (`computeClockMapping` returns `undefined`); no new probe can be registered while one is outstanding. The previous unit expectation that a late reply throws was changed because the requirement changed.
- **Nits.** New `queue-count-overflow`, `queue-bytes-overflow` and `queue-gap-missing` streams; `module` is available only with method `module-scan` (`game-mode-unknown-with-module` fixture); this verifier block.

### PR #42 advisory finding (October 14, 2026)

The advisory review on PR #42 found that `V1Consumer` compared a status `nextEventSeq` only with the previous status, not with the coverage already received on the connection. After a checkpoint with *N* = 1 and coverage of 1–4, a snapshot with `nextEventSeq: "2"` was accepted, contradicting the §9 coverage invariant. The consumer now rejects a status `nextEventSeq` below the next `eventSeq` the connection's coverage requires, as the `end` branch already did, and §7 and §9 state the rule. The new `snapshot-next-below-coverage` fixture is schema-valid; the new stream of the same name rejects it at step 5. With the condition temporarily removed, that stream failed (accepted, 1 failure of 276 tests in the two v1 files); with it restored, it passes.

## Deviations from the architect plan

- **Last assignable `eventSeq`.** The plan listed "a max-uint64 eventSeq" as accepted. A uint64 `nextEventSeq` cannot follow an event numbered 18,446,744,073,709,551,615, so the contract makes 18,446,744,073,709,551,614 the last assignable `eventSeq` (`MAX_EVENT_SEQ`). The max-uint64 value stays accepted for message `seq`, monotonic times and money, and `event-seq-uint64-max.json` is rejected.
- **Game-mode invariant.** "Unknown pairs with none" is implemented as: `unknown` if and only if method `none` and confidence `none`.
- **Game mode pointer in concept.md.** As the plan requires, a dated one-line pointer was added at the end of the existing "Game mode as a trip attribute" section. No earlier text was changed.
