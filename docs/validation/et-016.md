# ET-016 trip journal validation

## Scope and authorization

Under the owner's standing delegation of October 15, 2026 the coordinator started ET-016, the trip journal, trip details and JSON export, and adopted decisions J1–J22 ([concept.md](../../concept.md#et-016-authorization--october-16-2026)). The owner did not review them individually. ET-016a is five PRs: storage schema version 2 (PR-1), bounded journal reads in the storage worker (PR-2), journal queries from main through the telemetry service (PR-3), the Journal tab (PR-4) and versioned JSON export (PR-5). ET-016b is three PRs: fuel-used persistence (PR-6), late-attach trips (PR-7) and journal and export reconciliation in the recording journey (PR-8). `GAME_HISTORY_RECORDING` stays `false` throughout, so nothing in ET-016 records real game history, and no game, TruckersMP, display or performance claim follows from these checks.

### Changes

- `packages/storage/src/sqlite/schema-v2.ts` (new, frozen once merged): the statements of migration `0002-journal` (J6). `trips` gains `fuel_used_l` with `fuel_used_l_state` (default `not-observed`) and the close carrier `closed_by_session_ref` and `closed_by_event_seq` (NULL together, NULL while open). `job_configurations` is rebuilt with the SQLite 12-step procedure with `plugin_session_ref` (NOT NULL, backfilled from each row's event), `source` (`event` or `checkpoint`), a nullable UNIQUE `event_ref`, `checkpoint_next_event_seq`, CHECKs tying the source to exactly one reference and `UNIQUE (plugin_session_ref, checkpoint_next_event_seq)`. No index is added beyond the implicit index of that UNIQUE key. The review round below replaces the ADD COLUMN steps with a `trips` rebuild. The file repeats the version 1 column helpers instead of importing them.
- `packages/storage/src/sqlite/migrations.ts`: `MIGRATIONS` gains `{version: 2, name: '0002-journal', foreignKeysOff: true}`. `foreignKeysOff` applies only on the upgrade path: an existing version 1 database is backed up and verified first, as before, and migrated with foreign keys off. A new database receives versions 1 and 2 in one transaction with foreign keys on (`connection.ts`, the `inspection.fresh` branch), which is harmless because its tables are empty when 0002 drops and renames them.
- `packages/storage/src/sqlite/writes.ts`: `normalize()` writes `plugin_session_ref` and `source = 'event'` for every `job.configured` row. `trip.close` records the carrier in its transaction (J7): the committing session and the event's eventSeq, or for a gap `max(firstEventSeq, previouslyCoveredThrough + 1)`. A `trip.close` without a carrier context is `INVALID_INPUT`; only `commitEvent` and `commitGap` apply effects, and both set it. No write command changes otherwise.
- `tests/fixtures/storage/schema-v2-representative.{sql,sqlite,expected.json}` (new) and `manifest.txt` (three lines added). The SQL holds the `sqlite_schema` text that migrations 0001 and 0002 produce, in `sqlite_schema` order, and hand-chosen content: two plugin sessions, a delivered trip (carrier: its outcome event 2), a gap-closed trip (carrier: eventSeq 4, the gap's first newly covered eventSeq), a trip closed by a restart from session 2 (carrier: session 2, eventSeq 1), an open trip, fuel used 42.5, 0 and two unavailable states, and one checkpoint job configuration that no trip references. The database was created once from the SQL with better-sqlite3 13.0.3 (SQLite 3.53.4) under Electron 44.7.0 in Node mode, in rollback-journal mode; `foreign_key_check` was empty and `integrity_check` `ok`.

### Interpretations and deviations from the plan

- **Gap carrier.** The plan says `previouslyCoveredThrough + 1`. Storage uses `max(firstEventSeq, previouslyCoveredThrough + 1)`, the first eventSeq the gap newly covers: the two differ only for a gap that starts beyond coverage + 1, which the recorder's ordered FIFO does not produce. A dedicated case covers both shapes.
- **Carrier on an open trip.** Beyond "both NULL together", a CHECK keeps the carrier NULL while `outcome` is `open`, as J6 states it.
- **Checkpoint key range.** `checkpoint_next_event_seq` is a 20-digit key above zero, up to 2^64 − 1, because protocol v1 allows `nextEventSeq` up to that value.
- **`trip.close` without a carrier context** fails with `INVALID_INPUT` instead of writing NULL; no caller can reach it.
- **The orphan case.** The plan expected a failure inside 0002 to prove the rollback. A version 1 database with a broken foreign key never reaches 0002, because the verified backup refuses it; that case now asserts the refusal, and the rollback of 0002 is proven with an injected failing version 3 after it.
- **Existing tests changed because the requirement changed** (version 2 is current). `migrations.test.ts`, `backup-restore.test.ts` and `fixtures.test.ts` used a test-only version 2 step on top of `MIGRATIONS`; injected steps now start at version 3, and the cases that must read version 1 unchanged pass `MIGRATIONS.slice(0, 1)`. `worker.test.ts`, `open-durability.test.ts` and `recording-target.test.ts` expect a new database at version 2.
- **`tests/storage/failures.test.ts`** (not in the plan's owned list). Its `SQLITE_FULL` case caps `max_page_count` at the current page count. The 0002 rebuild leaves the old `job_configurations` pages on the freelist of a new database, so the event fitted into free pages and storage run 1 failed that case. The case now asserts a non-empty freelist, runs `VACUUM`, asserts an empty one, and then caps; the assertion on `DISK_FULL` is unchanged.
- **`RuntimeReceipt.ps1` and `tests/unit/runtime-receipt.test.ts`** (not in the plan's owned list, named in the task): the recording receipt rule accepted only `userVersion` 1; it now accepts only 2, and a negative case refuses a version 1 receipt.

### PR-1 review round 1 (October 16, 2026)

The independent review of `0ae2362` requested changes for one major gap: schema version 2 kept `trips.opened_event_ref INTEGER NOT NULL REFERENCES events (id)`, so a late-attach trip opened from a checkpoint (J9, S-2), possibly in a plugin session without any event, could not be stored. The coordinator amended J6: migration `0002-journal` also rebuilds `trips`. The coordinator added `a7a064b` (AGENTS.md and concept.md, the uninstall rule) on the branch in between; this round does not touch those files.

#### Changes (`1c28056`)

- `schema-v2.ts`: the three ADD COLUMN steps are replaced by a 12-step rebuild of `trips` after the `job_configurations` rebuild. `opened_event_ref` becomes nullable; the new `opened_by TEXT NOT NULL CHECK (opened_by IN ('event', 'checkpoint'))`, without a default, is tied to it by `CHECK ((opened_by = 'event' AND opened_event_ref IS NOT NULL) OR (opened_by = 'checkpoint' AND opened_event_ref IS NULL))`. Fuel used and the close carrier are created in the rebuilt table, with the same text as before, after `updated_utc_ms`. The carrier CHECKs became table constraints. Every other column, constraint and default keeps its version 1 text, written with the same helpers. Every version 1 row is copied with its id and `opened_by = 'event'`. The header now states that `foreignKeysOff` applies only on the upgrade path and that no index is added beyond the implicit UNIQUE indexes.
- Tables that reference `trips` (`trip_trailers`, `event_attributions`, `completeness_intervals`, `samples`) keep their rows and their `REFERENCES trips (id)` text, because the copy keeps every id and the rename restores the name. No trigger or view references `trips` or `job_configurations`. The dumped DDL shows four `REFERENCES trips (id)`, one `REFERENCES job_configurations (id)` and no `new_` name. `sqlite_autoindex_trips_1` keeps its name.
- `writes.ts`: `trip.open` writes `opened_by = 'event'`. Reads and `TripRecord` are unchanged; every trip written so far opens at an event.
- The unreleased version 2 fixture was recreated from its updated SQL (the new DDL, `opened_by` `event` for all four trips and the updated header), and `expected.json` gained `opened_by` in its hand-written trip columns. `manifest.txt` has the new SHA-256 values. A checkpoint-opened trip is not in the fixture, because the trip reads cannot return one before PR-7; `schema-constraints.test.ts` covers that shape.
- Tests: `migrations.test.ts` compares the migrated trip row with the version 1 row plus `opened_by` `event`, fuel used `not-observed` and no carrier, and every `trip_trailers`, `event_attributions`, `completeness_intervals` and `samples` row (1, 4, 1 and 3 rows) with its version 1 value. `schema-constraints.test.ts` gains "opens a trip either at a stored event or from a checkpoint without one", and its raw trip inserts name `opened_by`, which has no default. `fixtures.test.ts` reads `opened_by`. `trip-effects.test.ts` is unchanged and passes.
- Documentation (the docs commit after `1c28056`): [storage](../storage.md#schema-version-2-et-016) describes the `trips` rebuild, the foreign-key behaviour of both paths and the implicit UNIQUE indexes; the [registry](../regression-registry.md) row REG-013 and the ET-016 section of [TESTING.md](../../TESTING.md) follow.
