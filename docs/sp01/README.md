# SP-01: early game-to-overlay experiment

SP-01 is a bounded early package of [ET-009](https://trello.com/c/Y3qJd9aF/10-et-009-run-early-spike-capture-game-events-and-validate-the-prototype), following the accepted ET-001 scaffold. Its purpose is to test the official SDK → project DLL → local pipe → Electron speed/fuel overlay in actual games before designing the production protocol. Development is timeboxed to two development days after scaffold setup; actual game sessions are scheduled separately. Work began October 11, 2026. This code is isolated under `experiments/sp01`; it is not a production adapter, recorder, or compatibility claim.

The DLL copies speed, fuel, frame timestamps, pause state and timer-reset flags in SDK callbacks. A background thread drains a bounded 63-entry SPSC queue, coalesces snapshots, queries the foreground game client rectangle, serializes at up to 20 Hz, and serves one same-user local pipe client. There is no offline spool or history. Electron's utilityProcess owns the pipe client; main owns a transparent, nonfocusable, mouse-ignoring window and explicit exit tray item. The sandboxed React renderer receives a narrow subscription API. Missing readings remain distinct from zero; speed is converted from m/s to km/h, fuel remains liters.

This spike deliberately excludes jobs, journal/history, event persistence/ACKs, CAP-01 capture corpus, production protocol v0/v1, server work, final UI, rendering hooks, memory reads, exclusive fullscreen and the complete ET-009 matrix. Pause/reset flags are experimental snapshot metadata, not a durable event path. See [wire format](wire.md), [build and safe game workflow](workflow.md), [validation evidence](validation.md), and [actual game checklist](game-checklist.md).

Do not promote this source wholesale. After required sessions, record **proceed**, **investigate**, or **retire** with the observed evidence.
