# Disposable guest installer acceptance

This is a preparation and guest-only runtime workflow for ET-001. Electron, application and installation/removal runtime must not execute on the physical host during the recovery hold. Ordinary Node unit checks, builds and inert kit preparation remain allowed. The coordinator owns fixture building, kit preparation, transport, VM boot and its independent outer watchdog, interactive dispatch, export, shutdown and clean-snapshot restoration. Harness source fixes precede each reviewed kit freeze; application artifact bytes remain frozen.

The original maker Setup installs 0.1.0. The upgrade feed is a private test fixture with NuGet version 0.1.1 and byte-identical original 0.1.0 application runtime, including ASAR metadata. It is not a product version change or release. Build the fixture only from a disposable clone: electron-winstaller copies its Squirrel executable into its input app directory. Do not run its synthetic Setup. Use only the fixture full NuGet and local RELEASES feed.

It creates Node and fixed Windows PowerShell suspended as siblings. [PROC_THREAD_ATTRIBUTE_JOB_LIST and HANDLE_LIST](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-updateprocthreadattribute) atomically assign each process to that Job at creation and permit inheritance of only its own three standard handles. The Job handle is never in the inherited list or duplicated, so [closing its last handle](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects) on owner death kills both roots and descendants, including a partial startup. Each root has separate stdout/stderr drains retaining at most 1 MiB per stream.
